ℹ️ What does this view show?
The overview shows budget (from Product A) compared with actuals (from ERP). Use the filters at the top to select year, period and organization. The dimension switcher controls which dimension is shown in the table below.

Flex dimensions (Activity, Cost Center, Counterpart) come from the platform's routing — ERP data gets values automatically, budget data lacks these.
⚙️ Technical: Read Model + Flex Dimensions
Product B builds a read model by consuming egress topics:

Budget: platform.budget.out → { source_system, source_key, planning_dimensions, dim_values_per_line }
Actuals: platform.gl.out → { source_system, source_key, dim_values_per_entry }

Flex dimensions (Approach C):
  account, org_unit, period = named standard dimensions
  dim1, dim2, dim3 = generic flex dims with labels from dim-model

SQL: UNION ALL budget_lines + gl_lines
Filtering is done client-side on the complete dataset.
Chart rendered with Canvas 2D API (no external lib).

ℹ️ What happens if Product B goes down?
If this product is temporarily down, no data is lost. All events are stored in the queue and wait. When Product B starts again it automatically catches up on everything it missed.
⚙️ Kafka offset & catch-up
Consumer group (product-b-consumer) has saved offsets in Redpanda.
On restart consumer.run() resumes from latest offset.
At-least-once delivery + INSERT OR REPLACE = idempotent.

Ingestion Rules

Rules are applied to each incoming line (budget or GL) before storage. They run in priority order (lowest first). Default rules only set a value if the field is empty. Derive rules always overwrite.

ℹ️ What are ingestion rules?
When budget or GL data flows into Product B, each line passes through these rules before being stored. This lets Product B add product-specific enrichment — for example, deriving a cost category from the account number, or setting a default value for a dimension that the source system doesn't provide. The platform handles routing between systems; ingestion rules handle product-specific knowledge.
⚙️ Ingestion pipeline architecture
Kafka event (platform.budget.out / platform.gl.out)
  │
  ├─ Platform enrichment: source_system, source_key, planning_dimensions, dim_values_per_line
  │
  └─ Product B ingestion pipeline (per line):
       1. Merge original line + platform dim routing
       2. Load rules from ingestion_rules table (WHERE enabled=1 ORDER BY priority)
       3. Per rule: evaluate condition → if match, set target_field
          - "default": only if target is NULL/empty
          - "derive": always overwrite
       4. Store enriched line in budget_lines / gl_lines

This separation means:
  - Platform knows how to ROUTE dims between systems
  - Product B knows its own business logic (defaults, derivations)
